# Budget Explorer architecture

This Worker serves two kinds of sites from one codebase. The request host decides which one.

Data rules, payroll, the names switch, imports, and the D1 migrations stay in the repository root `ARCHITECTURE.md`. This file is the host routing and the public door. Do not apply migrations on the remote database from here. Do not change the admin names switch or hidden-mode reads for this front door.

## Hosts

| Host | What `/` is | County pages |
| --- | --- | --- |
| howtheyspendmytaxes.com | Public state map | Under `/walton`, password required |
| www.howtheyspendmytaxes.com | Same public map. Canonical links use the apex host. | Same `/walton` prefix |
| budget.whatshappeningnetwork.com | Walton dashboard, unchanged | At `/`, `/funds`, `/revenue`, and the rest |
| budget-explorer.352marc.workers.dev | Walton dashboard, unchanged | Same as the budget host |
| Any other host, including localhost | Walton dashboard, unchanged | Same as the budget host |

`isTaxesHost` in `src/host.ts` is the check. Only the two taxes hostnames match. A lookalike hostname does not.

## Public door

These pages are server-rendered HTML. The maps are inline SVG paths. There is no map library, no map tile server, and no extra third-party request beyond the Fraunces and IBM Plex Sans stylesheets the dashboard already uses. Shapes are generated by `scripts/build-maps.mjs` from the public domain U.S. Census cartographic boundaries redistributed in the `us-atlas` package (Albers USA, 1:10,000,000) and the Census 2020 county name file in `scripts/census/national_county2020.txt`. The name file lives outside `data/` because that folder is gitignored. The script writes `src/geo/states.json` and `src/geo/counties/florida.json` only. Other states are on the national map and do not get a county file. Regenerate with `npm run maps`. The Worker does not fetch a map at runtime.

- `GET /` is the national launch page. The hero is a state and county picker beside a real state map. Florida is gold because it has a live county. Every other state is a muted coming soon color and still opens its state page. Alaska and Hawaii sit where the Albers USA projection places those insets. The District of Columbia is drawn in place and again, larger, in a box to the east. Rhode Island and Delaware include a wider invisible hit target because their shapes are small. A "Skip to the state picker" link sits in front of the state links. On a narrow screen the picker is first and the map is second. Both stay on the page.
- The picker is a GET form to `/pick`. Without JavaScript, choosing a state and pressing Go opens `GET /{state}`. The Florida county select is in the form and lists only Walton County and "Request your county". A script hides that select unless Florida is chosen. `/pick?state=florida&county=walton` redirects to `/walton`. `/pick?state=florida&county=request` redirects to `/florida/request`. Any other county value, including a Texas county, is ignored and the state page opens. An unknown state redirects to `/`. The `to=request` value redirects to `GET /{state}/request`. The target is never taken from the query string as a URL. `GET /data/counties/{state}.json` still returns names and slugs only, `noindex`, and the homepage does not use it to build a county list.
- `GET /florida` is the only state page with a county map. It has its own title, description, canonical URL, Open Graph tags, and `WebPage` JSON-LD. The map is `src/geo/counties/florida.json`. Counties stay in one Census Albers projection, with the Panhandle attached to the peninsula and the Keys included. The map fills the width of the page. Walton County is the only link, and it goes to `/walton`. A short Walton label with a leader line sits on that county. The other 66 counties are outlines with the title "Coming soon". There is no county list and no county dropdown on this page. One "Request your county" button sits under the map. `GET /states/florida` redirects to `GET /florida`.
- A coming soon state page says "coming soon" in the headline only. Its footer does not repeat "Request your county", because the form is headed "Request this state".
- `GET /florida/walton` redirects to `/walton`. Every other `GET /florida/{slug}` redirects to `/florida/request`. Those paths are not pages, they are not in the sitemap, and `/florida/request` is `noindex`.
- `GET /{state}` for every other state, including Alaska, Hawaii, Texas, Louisiana, Virginia, and the District of Columbia, is a coming soon page. It has no county map and no county list. A small silhouette of that state is drawn from the national map. The same request form is on the page, headed "Request this state", with the state filled in and the county name typed by the visitor. The page is `noindex`. `GET /states/{state}` redirects to `GET /{state}`. A path such as `/georgia/walton` is not a county page.
- Walton County is the only live county. `COUNTIES` in `src/places.ts` is still the live override list.
- `GET /florida/request`, `GET /{state}/request`, and `GET /states/{state}/request` ask for a county that is not chosen from the map. The state is filled in. The visitor types the county name. A typed name that matches a live county, after dropping the word County and punctuation, says that county is already live and does not save a row. That page is labeled already live. It does not say the note was received, and it does not tell the visitor to close the page. The form is a normal POST with a CSRF cookie, an origin check, a honeypot field, and a limit of 5 saves an hour for each network. A network is the full IPv4 address, or the first 64 bits of an IPv6 address, hashed before it is stored. Public forms read that address only from the `CF-Connecting-IP` header. If the header is missing, or the value is not an IP address, the form responds with 503 and a short page and does not save. County requests and data notes together stop at 200 saves in an hour and 1,000 saves in a day. Past either cap, the form responds with 503 and a short page. Public pages send `Referrer-Policy: same-origin`. A post whose `Origin` is the string `null` is accepted only when `Sec-Fetch-Site` is `same-origin`. Rows go in `county_requests`. The page never prints an email address. The thank-you page says the request was saved. The Worker does not send email.
- `GET /request` is the footer "Request your county" page. It is `noindex`. `GET /about-this-site` is a short public About page. It is not in the sitemap.
- Logged-out `GET /walton` is a public landing with a short explanation and the password form. The explanation says the page is unofficial, that the figures come from public records provided by the Walton County Clerk and Comptroller, and that access is currently private. The page is indexable. The form posts to `/walton/login`.
- Logged-in `GET /walton` is the same dashboard other hosts serve at `/`.
- `GET /walton/login` and every other county page are `noindex`. The login page repeats the unofficial explanation.

The public homepage does not print county dollar figures. The existing unofficial banner, including the data-as-of line, stays on pages that show county data. No county seal is used.

## Prefix and bookmarks

On a taxes host, dashboard routes are mounted by rewriting `/walton/...` to the existing route and then prefixing root-relative links and `Location` headers in the response. Shared files stay at `/assets/*` and `/favicon.svg`.

Nav targets come from `PUBLIC_PATHS` in `src/view.ts`. `DASHBOARD_PREFIXES` in `src/host.ts` must cover that list, plus login, logout, and admin. Tests check the nav list.

`GET` and `HEAD` to an old unprefixed path redirect `301` to `/walton/...`, including the query string. Examples: `/funds/001` to `/walton/funds/001`, `/revenue` to `/walton/revenue`, `/search?fund=114` to `/walton/search?fund=114`. A signed-out deep link such as `/walton/funds/001` still redirects to `/walton/login` with `next` set to the prefixed path. `POST` to an old path is forwarded, not redirected, so a password form still works.

A request path that starts with two slashes, or with a slash and a backslash, is the public 404. The same is true when the path decodes to one of those, including `%2f%2f` and `%5C`. Trailing-slash redirects stay for ordinary paths such as `/florida/`. Any `Location` built from a request path or a `next` value collapses leading slashes and backslashes first, including inside `taxesTarget` and when a dashboard `Location` is rewritten. The header is a single-slash path on this host. It cannot be scheme-relative or protocol-relative.

## Who was paid

The password-protected dashboard leads with vendors and payments. The chart pages stay.

- On the overview, a search box opens the existing payment search. Under it, "Who received the most money" lists the same outside vendors as the vendor chart: grouped by vendor number, longest stored name, object `591000` left out, county offices left out, person names left out, and lines after the report date left out. Each numbered vendor links to `/vendors/{number}`.
- `GET /vendors` lists those vendors. It can be searched and sorted by total received or by the number of payment lines.
- `GET /vendors/{number}` shows total received, the number of payment lines, the first and last payment date, totals by fund and by department, and the payment lines (date, amount, fund, department, account, description) with pages. Reversals and re-posts stay separate lines. Hidden mode uses the same name rules as payment search.
- `GET /search` is the payments page. Filters are vendor, department, fund, date range, and amount range. `GET /search.csv` downloads the filtered rows, at most 2,000 lines. These routes are the same login gate as the other dashboard pages, including under `/walton` on the taxes host.
- The footer, About the data, and the overview budget headline link to https://budget-waltoncountyfl.com as the county's own FY2027 tentative budget book. This site does not load FY2027 amounts.

## Search

Canonical URLs, Open Graph tags, and JSON-LD use `https://howtheyspendmytaxes.com`. The homepage JSON-LD type is `WebSite`. Florida and the Walton landing use `WebPage`. There is no `Organization` node: the site is not a county agency, and the copy does not name a publisher.

`GET /sitemap.xml` on a taxes host lists `/`, `/florida`, and `/walton`. It does not list other state pages, county coming soon pages, `/report`, `/request`, `/pick`, `/data/`, or any password-protected page. Other state pages send `noindex`. `GET /robots.txt` on a taxes host disallows each `/{state}/` prefix, `/walton/`, `/states/`, `/report`, `/request`, `/pick`, and `/data/`. On every other host, `robots.txt` is still `Disallow: /` and responses stay `noindex, nofollow, noarchive`.

The committed geometry is about 46KB for the national map and about 12KB for the Florida county file. Alaska and Hawaii have light inset frames. Rhode Island, Delaware, Hawaii, and the geographic District of Columbia have a wider invisible hit target. On a phone, tapping a state selects it and a large Open button follows the link. There is no map JavaScript library.

## Notes from visitors

Every page footer links to "Report a problem or share an idea".

- On the taxes host the form is `GET /report`, and the Walton dashboard link is rewritten to `GET /walton/report`. Both work without the site password. They are `noindex` and they are not in the sitemap.
- On budget.whatshappeningnetwork.com and the workers.dev host the form is `GET /report`, also without the site password.
- The first field is "What is this about?" with two choices: "Something looks wrong" or "An idea for using this data better". The choice is stored in `data_reports.kind`.
- A problem asks what page or number looks wrong (filled in from the page the visitor left, when that page is known) and what they think is correct. An idea asks for "Your idea" and does not need a page.
- Source, name, and email are optional. The county is required, and the form says so in plain words. Email is stored and is never printed. The thank-you page says the note was saved. The Worker does not send email.
- The form uses the same CSRF cookie, origin check, honeypot, 5-an-hour network limit, and the shared 200-an-hour and 1,000-a-day caps as a county request. It reads only `CF-Connecting-IP`. A missing header is a 503.

Migration `migrations/0004_county_requests.sql` creates `county_requests` and `data_reports`. Apply it on the remote database by hand. Do not run `wrangler d1 migrations apply --remote`.

## What this change does not do

It does not deploy. It does not run remote migrations. It does not change how person names are stored or hidden. It does not add a contact email and it does not send mail.
