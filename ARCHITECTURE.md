# Architecture

This repository holds two Cloudflare Workers. They do not share config, bindings, or a hostname.

## What's Happening

Static company site for What's Happening, a marketing and media company. One page covers the work, the current projects, and the team.

- Worker name: `whatshappening`
- Config: root `wrangler.jsonc` and `worker.js`
- Public site name: whatshappeningnetwork.com
- The root Worker config does not attach a custom domain. DNS stays unset in that file.
- There is no database. The team list is `data/team.json`, with photos in `photos/`.
- Contact form: `POST /api/contact` sends mail through Resend. Secret names only: `RESEND_API_KEY`, `CONTACT_EMAIL`. Do not commit the values.
- Deploy from the repository root: `npm run build`, then `npx wrangler deploy`.

## Budget Explorer

Private prototype for reading a Walton County year to date budget report, plus a public front door on howtheyspendmytaxes.com. It is budget software only. It is unofficial and it does not use the county seal. Password-protected county pages stay out of search indexes. The public state and county door on the taxes host is indexable.

- Purpose: show each fund and department budget next to what has actually been spent. Pages also include payment search, a recreation plat fee history, and questions answered only from imported rows.
- Worker name: `budget-explorer`
- Project directory: `budget-explorer/`
- Domain: budget.whatshappeningnetwork.com
- workers.dev hostname: budget-explorer.352marc.workers.dev
- Public door: howtheyspendmytaxes.com and www.howtheyspendmytaxes.com are the same Worker. Host routing is in `budget-explorer/src/site.ts` and `budget-explorer/src/host.ts`, and is described in `budget-explorer/ARCHITECTURE.md`. On those two hosts, `/` is a public national page: a Census state map and a state and county picker. Florida is the only state with a county map, from `budget-explorer/src/geo/` (built by `budget-explorer/scripts/build-maps.mjs`). Walton County is the only live county and the only clickable Florida county. It links to `/walton`. The other Florida counties are outlines, and `/florida/{slug}` for any other slug redirects to `/florida/request`. Every other state opens a coming soon page with the same request form, headed "Request this state", and stays `noindex`. There is no county map outside Florida. The password-protected Walton dashboard that other hosts serve at `/` is served at `/walton`. Public pages send `Referrer-Policy: same-origin`. A form post with `Origin: null` is accepted only when `Sec-Fetch-Site` is `same-origin`. Typing a live county, including "Walton County", says that county is already live and does not save a request. `COUNTIES` in `budget-explorer/src/places.ts` is the live override list. On budget.whatshappeningnetwork.com and the workers.dev host, paths are unchanged and `/` is still the dashboard. Old unprefixed dashboard paths on the taxes host redirect to `/walton/...`. `sitemap.xml` on the taxes host lists `/`, `/florida`, and `/walton`. Other state pages and county coming soon pages stay `noindex`. There is no Organization JSON-LD, because this site is not a county agency and the copy does not name a publisher. `/report` (and `/walton/report` on the taxes host) is a public noindex form for a problem or an idea. It does not require the site password. County requests and those notes are stored by migration `0004_county_requests.sql`. Apply that file on the remote database by hand. Do not run `wrangler d1 migrations apply --remote`. The Worker does not send email, and it never prints an email address on a page.
- D1 database: `budget-explorer` (binding `DB`). The id is in `budget-explorer/wrangler.jsonc`. Migration `0001_init.sql` is already applied remotely. Migration `0002_settings.sql` adds the names switch and payroll line storage. Migration `0003_revenue_reserves.sql` adds the published income and savings tables. Apply `0003` on the remote database by hand. Do not run `wrangler d1 migrations apply --remote`. Load the rows with `budget-explorer/scripts/import-published.ts` after the tables exist. The script reads `budget-explorer/sources/revenue.json`, `reserves.json`, and `beach-vending.json`, checks that the shares add to the published totals, and writes SQL outside the repository. Pass `--budget-csv` with `--adopted-total` (dollars) and repeatable `--exclude-fund` to roll up a later budget file by account code. Unknown codes stop the import. `--apply` loads the SQL into the local D1 file only.
- Workers AI binding: `AI`. The model id is the constant `AI_MODEL` in `budget-explorer/src/qa.ts`. The model only sees rows retrieved for that question. Vendor totals, a named fund, the county budget, and transfer questions are answered from SQL in `budget-explorer/src/answers.ts` and do not call the model.
- Public totals leave out object code `591000` (money moved from one county fund to another). Adopted, the mid-year limit, and paid-out figures on the site are the report columns minus those transfer rows. The transfer amount is shown on its own. The admin import preview still shows the printed report totals so an import can be checked. Default answers do not quote the raw report totals. A question about transfers may. Payment search leaves out object `591000` unless the request includes `transfers=1`.
- The overview headline states the adopted budget and what the books show spent. It does not state a percent of the mid-year limit. That share, from `spent_of_current_tenths` in `BUDGET_FACTS_SQL`, appears only under the adopted-and-limit chart, labeled as a share of the mid-year limit. The higher figure is labeled "budget limit after mid-year changes" and is described as a ceiling. When the limit is above the adopted budget, a separate note says the Nov 24, 2025 carry-forward resolution (Resolution 2025-82) totals $185,438,075.92 (about $185.4M): $144,713,465.48 cash carried forward for unfinished projects and open purchase orders plus $40,724,610.44 of grants carried over. About $2.7M of new grants are visible in the report. About $7.3M is not itemized in the records we have. Total growth is $195,495,223.26. The note does not call open purchase orders an amendment. Sources: https://walton.civicweb.net/document/509733/ and https://walton.civicweb.net/document/520074/. The page does not explain spent dollars as the result of that resolution. Not yet spent or promised is the mid-year limit minus posted spending minus open orders, net of transfers.
- `/funds` and `/funds/:code` are fund pages. `/departments` and `/departments/:dept` stay the department drill-down. Each of those pages leads with the adopted budget, the budget limit after mid-year changes, and paid out, then where the money went. Largest payments are outside payments: object `591000` and county-office vendors are excluded before the row limit. The person filter on that query uses the stored `is_person_name` column, because `sqlIsPersonName` plus the office filter exceeds D1's expression depth of 100. Hidden mode still requires `is_person_name = 0`. A positive line is omitted when a negative line reverses the same vendor and amount, and a blank name is not shown again when that amount is already listed for a vendor within 14 days. The list is also capped by each vendor's net total. A payment line larger than that page's paid-out total is left off, and a short note says when a payment is recorded on more than one account. Department names that repeat get the fund name, or only the department code when the fund name repeats the department's words. When spending above a department budget is covered by object codes starting with `56`, the row names that account (Land for `561000`) instead of an over-budget alarm.
- Vendor names on public pages are the stored report name in title case, with trailing punctuation removed. A person name with a middle initial stays as stored. The site does not expand a cut-off name from a longer row and does not drop a word to guess a shorter name. A name of 20 characters, or one ending in `*`, is marked "Name shortened in the county report". Bars that display as the same cleaned name are added together. A vendor whose name is exactly Walton County is counted with other county offices. Questions match vendor names with punctuation and apostrophes removed, then a prefix check, before any model call. A payee answer says payments, using the distinct payment count, and does not call that count checks.
- Content Security Policy allows the Cloudflare Web Analytics script at `https://static.cloudflareinsights.com` and its beacon at `https://cloudflareinsights.com`. No other third-party script or connect hosts are allowed.
- Secret names only. Do not commit values.
  - `SITE_PASSWORD` (required): shared site password
  - `SESSION_SECRET` (required): HMAC key for the session cookie
  - `ADMIN_PASSWORD` (required): Admin pages stay off until this is set. Unlock failures are throttled per IP and for all visitors together. The field is only on `/admin/unlock`
  - `PUBLIC_BASE_URL` (optional): shown on About when it is an http(s) URL. Links in the app stay relative.
- Deploy: Cloudflare Workers Builds from `main`, root directory `budget-explorer`, deploy command `npx wrangler deploy`.
- Data import: an administrator uploads a text report on the Admin Import page, reviews the preview, and publishes it. CSV or Excel can supply chart of accounts names. PDF uploads are refused. County reports, parsed JSON, and payment extracts stay out of git. `budget-explorer/data/` and `seed.sql` are gitignored. The seed script writes its SQL file outside the repository, in the system temp directory. The root `.assetsignore` excludes `budget-explorer` and `seed.sql`, so a deploy of the placeholder Worker cannot publish them. For a full year file that is too large for one Worker request, `budget-explorer/scripts/seed-local.sh` loads a local D1 copy only.

Gotchas:

- The GitHub repository is public. Do not commit county payment rows, payroll detail, or secret values.
- Payroll employee names and individual pay are stored on every import. One admin switch, "Show person names and individual pay", controls whether they are shown. The default is on, from `SHOW_PERSON_NAMES_DEFAULT` in `budget-explorer/src/access.ts`. The switch lives in D1 (`settings`) and is changed only by `POST /admin/settings` after the admin unlock, with CSRF. Each change is written to `settings_log` with a timestamp. Turning it off does not require a re-import.
- When the switch is off, `budget-explorer/src/access.ts` is the only reader for payments, payroll lines, search, drill-down, plat lines, CSV export, and question context. Hidden queries do not select employee names. Whether a vendor is a person is decided when the row is read, not from the stored `is_person_name` flag, except the fund and department largest-payment query and the overview vendor list. Those two statements use the stored flag so they stay within D1's expression depth. A vendor is treated as a person unless it is clearly an organization. Description text in Last, First form is scrubbed on those same reads, including question context and the model answer. Payroll groups of at least 3 lines and at least $1,000 are returned as "Payroll (batch total)". Smaller groups are rolled into "Other payroll" only when that rollup clears the same bar, and omitted otherwise. The model answer and its citations are filtered again before the page is rendered. There is no JSON API for these rows.
- A payroll batch with fewer than 3 lines is folded into a combined monthly total and flagged `below_minimum`. The folded batch is still stored, so those dollars stay reachable. Hidden mode does not show a stored group that is still under 3 lines or under $1,000 as its own total.
- Non-vendor detail lines keep coded fields only. Raw narrative text from those lines is not stored.
- Vendor payments that look like a person stay in the import. The import preview does not list those names. When the switch is off, the row remains and the name is shown as "Name withheld". Description names in Last, First form are removed even when the vendor is an organization.
- Plat fee history shows published imports. Draft imports show there only after an admin unlock, and they remain on the admin import list.
- An import can be published only when the stored fund, department, account, payment, payroll batch, and payroll line counts match the parse.
- Lines dated after the report date (for the current file, after 9/15/2026) are stored and flagged. Search, account payment lists, plat activity, questions, the monthly spending chart, and vendor totals exclude them.
- `/revenue` is audited FY2025 income by source, plus later years labeled Budget. Transfers between funds and savings brought forward are shown apart from income. `/reserves` is the audited year-end fund balance at September 30, 2025, by classification and by fund. A fund page shows that fund's savings split when the published row has the same fund code. The overview adds a smaller income pie beside the spending charts, with links to both pages. Navigation includes Revenue and Reserves. `PUBLIC_PATHS` in `budget-explorer/src/view.ts` is the signed-in page list. Charts are server-rendered SVG. No chart library is shipped. The files in `budget-explorer/sources/` are published aggregate totals and source URLs only. They are not payment lines or person names.
- The overview is calculated from the published import on each request. On budget.whatshappeningnetwork.com and the workers.dev host it is `GET /`. On howtheyspendmytaxes.com it is `GET /walton`. Headline, KPI cards, fund bars, the share donut, the income pie, department pace, monthly columns, organization vendors, the worth a look panel, and the fund 114 card are server-rendered HTML and inline SVG. No chart library is shipped. Interfund transfer departments and Solid Waste Transfer are left out of the pace chart. The departments list tags those rows Transfer, not spending. The vendor chart lists outside organizations only, in both positions of the names switch. It leaves out object `591000` and payments whose vendor is a Walton County office (the name Walton County itself, or a name starting with Walton County for the sheriff, property appraiser, tax collector, clerk, supervisor of elections, or the board, including names cut off at 20 characters such as Walton County Superv). Those office payments are one labeled row, with no office names from the payment rows. Vendors that share a vendor number are shown under the longest name stored for that number. Money moved between funds is a separate labeled amount. Person names and individual pay are not selected for this page. Pace compares money spent with the year percent shown on the page, rounded to a whole number: in line, under, or spending more than the year's progress. The pace pill uses that same wording. Fund 107 and the Sheriff department say Releases to the Sheriff instead of In line or Ahead. Clerk of Court and Tax Collector say Paid on schedule instead of Ahead.
- A question that names a payee is answered from vendor payments when one matches. If none matches, the question continues to fund, department, and account facts, then the model. "Who is paid the most?" uses the largest outside vendor.
- Fund detail is `GET /funds` and `GET /funds/:code`. Payment search accepts `fund`, `from`, `to`, and `transfers=1`, as well as the older filters. Without `transfers=1`, search totals leave out object `591000`. The overview spent figure is the account report's year-to-date column minus object `591000`. The label is spent, posted in the county's books through the report date. The search total adds payment lines and payroll lines, and it leaves out lines dated after the report date. Those are different totals. Search says so on the page, and it says reversals and re-posts are separate lines. Bars, months, vendors, funds, departments, and KPI cards link to those views. The overview card for what is not yet spent or promised uses the compact dollar form so a full dollar figure does not overflow the card. The overview pace sentence states spent as a share of the mid-year limit.
- The overview question box posts to `POST /ask` with the same CSRF check, rate limit, and sign-in requirement as the Ask page.
- Fund, department, object, and vendor totals in a question are summed in SQL before the model runs. The prompt tells the model to copy those figures and not to do arithmetic. Names match whole words, so a short word does not match inside a longer one. A fund match is used unless the question says department or contains an 8 digit department code. Each fact includes the account count and account keys.
